# 运行审计契约（2.x）

所有记录由真实读取/检索产生，不复制测试数据当事实。脚本只核对结构、白名单、痕迹及哈希，不能证明实际阅读、人工核实或真实视觉检查；需执行者完成这些工作。不得将自动设置布尔字段作为操作已发生的证据。

## research.json 顶层

- `schema_version`: `2.0`。
- `monitoring_period`: `{start: YYYY-MM-DD, end: YYYY-MM-DD}`，必须与本轮用户参数一致。
- `local_inputs`: `{requested: bool, paths: [], files: []}`。
- `sources`: 全部引用来源数组。
- `disease_sections`: 全部配置病种的四部分充分性记录。
- `records`: 全部名单国家和地区的逐病种核查。

## 本地输入

可选 `recursive` 默认为false，仅用户明确要求纳入子目录时设true；不跟随目录外链接，非资料文件不得执行。`requested`只表示用户是否要求/提供额外本地疫情资料；不是疾病简介是否必读。false时仍须在files登记已读技能简介；true时paths须含用户指定目录或上传文件实际绝对路径，不得为空。files每项为 `path,sha256,read_status,locator`，文件实际存在、哈希匹配，读取状态为“已读取/读取失败/未读取”。正式成稿使用的必须已读取。疫情文件必须位于声明输入范围；技能简介允许位于固定简介目录。不能用空目录或简介目录冒充用户疫情资料。

文件路径不存在、用户资料未读或未登记须报告具体路径及建议本地资料目录；不将默认目录当作用户授权。

## sources条目

每条具有：`id,type,locator,read_status,verification,country_code,disease,data_date,source_date,access_date`，以及可选的 `authority_type,authority_basis`。

- `authority_type`：来源权威性类型，取值见脚本常量 `AUTHORITY_TYPES`（`official/media/international/academic/other`）。普通来源可省略；但作为疾病简介缺失回退（intro fallback）的官方来源必须为 `official`，且 `authority_basis` 必须非空（说明权威性依据，如机构性质与官方网址）。脚本只登记字段、不证明实际访问，URL 须为真实访问记录。
- `authority_basis`：权威性的文字依据；intro fallback 的 official 来源必填非空。

- `type`: `local`或`web`。
- local：填`path`；如有原始URL填`source_origin_url`，不填web的url字段。path对应local_inputs.files；病例源可同一文件拆多条国家×病种证据。local条目仅用于内部总账和Excel本地证据清单，不直接输出到Word/PDF。
- web：填实际读取的HTTP(S) `url`，locator为标题/表格/节锚点。空结果不能伪造URL。Word/PDF的所有可见来源只能来自已核实web条目的URL；`source_origin_url`须另行实际访问并登记为web条目后才能展示。
- `country_code`: 名单内代码；配置病种的全球汇总或通用简介使用 `GLOBAL`，不得作为某国事件唯一依据。
- `disease`: 配置内规范病名。
- `data_date/source_date`: YYYY-MM-DD；确未公布用“未公布”。`access_date`必须为实际日期。
- `verification`: “核实一致”“人工核实一致”“人工核实存疑”“未人工核实”。仅实际有人类审查时用人工核实一致；智能体实际内容核查后可用核实一致，不伪称人工审核。仅可信、核实一致的来源支持正式事实；待核实线索不能做病例排序事实。

`internet_searches`每项：`query,tool,search_date,status,result_source_ids`，status=已完成/未完成。记录实际检索入口，结果编号须指向web来源，不能用local记录冒充网上补检。缺资料要补检到有可核实证据或具体外部阻断；失败查询保留但不算已完成补检。

## disease_sections条目

`disease,category,intro_file,intro_read,intro_locator,sections`，以及可选的 `intro_fallback_reason`。

`intro_file`与简介索引相对文件名一致；本地已有对应简介时必须真实存在且已读，overview引用该文件对应的local source。简介缺失（索引为 null / 新增病种键缺失 / 索引指向文件不存在）时：`intro_file` 置空（不得伪造文件名）、`intro_read=false`、`intro_fallback_reason` 非空（说明替代的权威来源 URL、标题、发布日期、访问日期与替代原因）；overview 须 `local_sufficient=false` 并留下真实完成的网络检索，且至少引用一条同病种、已读取、已核实、`authority_type='official'`（authority_basis 非空）的网络来源；失败/未读/未核实/仅媒体/来源不同病种/有搜索无对应引用均不得替代本地简介。已有本地简介不得借回退跳过。

sections四个键：`overview,global,countries,risk`；每项为：
- `sufficient`: 能否以证据支撑对应部分；false时写`reason`。
- `local_sufficient`: 本地是否足够；false必须实际联网并引用web证据，true必须引用本地证据。
- `evidence_ids`: 实际已读、同病种的来源id，充分时至少有一条核实一致来源。
- `internet_searches`: 上述搜索记录；无须联网时可空数组。

不将缺少一个次要字段机械视为整节不可写：完成相应检索后可据证据写明确的数据限制；但不能以“未公布”为名跳过补检或伪称无疫情。生成Word/PDF前另做公开来源投影：只把已核实web证据的HTTP(S)链接写入来源段，严禁输出research中的local path、locator、sha256、证据id或 `LOCAL:`。若某项正文事实仅由local证据支撑且无已核实web证据，该事实不得进入Word/PDF。

## records条目

每国一条：`country_code,country_name_zh,research_status,disease_checks`；research_status为“已完成/检索未完成”。

disease_checks必须恰好覆盖全部配置病种，每项：`disease,category,status,reason,evidence_ids,internet_required,internet_searches`。

- status：“已完成并纳入/已完成未纳入/检索未完成”。未纳入或未完成须写reason；未完成不能写无疫情/零病例。
- 完成须同国同病证据；纳入须同国核实一致证据，GLOBAL只作背景。
- `internet_required=false`用于纯本地证据足够的检查；引用web时改true并留检索痕迹。
- `internet_required=true`需要实际完成web搜索和读取结果；本地不足不得改false逃避补检。

范围示意为N×D检查，不在规范里写死数字。

## 命令与门禁

P0a名单，P0b病种/分类，P0c本地简介与模板；P1机构台账（独立JSON的records，字段见机构规则）；P2上述research完整性；P3调用生成器；P4落盘Excel/Word结构及Word公开来源校验（只允许HTTP(S)，阻断本地文件来源泄露）；P5渲染检查。

使用 `--help` 查看各脚本参数。各脚本支持显式配置路径用于测试或用户明确指定配置副本；正式本轮默认必须使用本技能指定两文件，不用别的名单绕过限制。

生成器命令通过 `build_deliverables.py --builder` 在前置通过后运行，只读取已核实材料并创建新的交付件；不改源模板、本地资料或名单。支持 `--template-copy` 创建生成器使用的新副本。默认内置模板含指导，不得直接将模板副本当正式报告。

`--renderer`接真实渲染命令；支持参数位置 `{docx}`、`{render_check}` 替换；`--builder`放命令尾部。渲染结果JSON：`docx_sha256, checked: true, pages: 正整数, issues: []`，由真实渲染和视觉检查后产生。哈希必须匹配最终文件；改过Word必须重新渲染，不复用旧结果。字体缺失或未完成视觉审阅不能伪填checked。

自动校验测试：`python -m unittest discover -s scripts/tests`。测试夹具均为独立模拟数据，仅验证代码行为，不能作为本轮事实来源。
